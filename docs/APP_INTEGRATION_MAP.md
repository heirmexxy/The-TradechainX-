## Architectural issues outside the contracts

1. **The backend trusts the browser about on-chain state.** `assets/controller.js mintAsset` records
   whatever `tokenId` and `transactionHash` the client sends; nothing in the backend fetches a receipt
   or decodes an event. A user can mark an asset as minted, or claim someone else's token, with a crafted
   request. **Fix:** an indexer that reads contract events (`ReceiptIssued`, `LienGranted`, …) and is the
   only writer of on-chain fields in MongoDB.
2. **A liquidation bot runs every 5 minutes** (`jobs/shedule.js` → `liquidate-job.js`) with its own hot
   wallet, calling `Marketplace.liquidate` on every listing. It currently fails every time because of the
   expiry bug (review item H1), burning gas. It depends on the guaranteed-premium design (review C5).
   **Fix:** delete it; the rebuild has no liquidation premium.
3. **KYC lives only in MongoDB.** Nothing on-chain knows who is verified, so contracts can't enforce it.
   **Fix:** when the admin approves KYC/KYB, the backend (holding the KYC Reviewer key, ideally via a
   KMS-backed relayer) calls `IdentityRegistry.setIdentity`.
4. **Contract addresses are hardcoded in three places** (`backend blockchain/index.js`, `admin contracts/index.js`,
   `frontend utils/index.jsx`), and the frontend defaults to chain id 1 when no wallet is connected.
   **Fix:** one per-chain address config, generated by the deploy script. Needed anyway for multi-chain.
5. **Wallets are injected (MetaMask).** The PRD's embedded, gasless wallets (§8.3–8.4) are a frontend
   and backend change, not a contract change; the new contracts work with ERC-4337 smart accounts as-is.
6. `user.js` model has unused `ethAccount/btcAccount/tronAccount.privateKey` fields from a template.
   Nothing writes them; drop them so no one starts to.

## Call-by-call migration

### Frontend (user wallet)

| Old call | Where | New |
|---|---|---|
| `submitReceiptDetails(qty, uri, basePrice)` | `dashboard/assets/index.js` | **Moves to the warehouse.** `WarehouseReceipt.submitReceipt(terms, holder)` is called by the warehouse operator, naming the depositor as holder. Traders no longer self-submit receipts. |
| `submitCreditDetails` | same | `CarbonCredits.submitBatch(terms)` by a verified originator, with registry reference. |
| `mint(submissionId)`, `mintingFees` | `dashboard/assets/[id].js` | **Removed.** Minting happens inside the reviewer's approval; the holder does nothing. Any issuance fee moves off-chain or to the marketplace. |
| `createListing`, `setApprovalForAll`/`approve`, `listingFees` | `assets/[id].js`, `profile/my-nft/[id].jsx` | New marketplace: listing moves the receipt into escrow (so it can't be sold twice). |
| `buy`, `resaleFees`, TXC `approve`/`allowance` | `marketplace/buy/[id].jsx` | New marketplace, settled in a stablecoin (USDC via the OMS ramp), not TXC. |
| `invest`, `claimYield`, `redeem` | `fractional-marketplace/buy/[id].jsx`, `profile/my-investment/[id].jsx` | New XOwn vault. |
| — | new | Pledge screens: `grantLien` (holder), `releaseLien` / `enforceLien` (lender). Redemption request: `requestRedemption`. |

### Admin

| Old call | Where | New |
|---|---|---|
| `processSubmission(id, bool)` / `approveSubmission(id, bool)` | `views/pages/Asset/index.js:438` | `approveSubmission(id)`, `rejectSubmission(id, reason)`, `requestInfo(id, reason)`. Reviewer wallet must hold `LISTING_REVIEWER_ROLE` and can't be the warehouse's operator. |
| `createAsset`, `distributeYield`, `markAssetAsMatured` | `Asset/FractionalAssettable.js`, `Asset/CreateAsset.js` | New XOwn vault; yield distribution must deposit real funds. |
| `setFees` | `contractManagement/index.js` | Stays (new marketplace, capped). |
| `withdrawTokens` | `contractManagement/index.js` | **Removed.** Fees go straight to the fee collector; user funds are never withdrawable by admin. |
| KYC approve (DB only) | KYC pages | Also writes `IdentityRegistry.setIdentity` via backend relayer. |
| — | new | Warehouse Registrar screen (`registerWarehouse`, suspend/reinstate); status-change queue (`confirmWarehouseRelease` is warehouse-side, `approveStatusRequest`/`rejectStatusRequest` reviewer-side); pause button for the pauser multisig. |

### Backend

| Old | New |
|---|---|
| `blockchain/liquidate.js`, `jobs/*` | Delete. |
| `mintAsset` trusting client `tokenId`/`txHash` | Event indexer writes token ids, owners, liens and statuses. API endpoints read from it. |
| Hardcoded addresses + ABIs in `blockchain/` | Generated per-chain config and ABIs from the Foundry build. |
| `LIQUIDATE_PRIVATE_KEY` hot wallet | Replaced by a KYC-reviewer relayer key, in a KMS, with the lowest possible role. |
